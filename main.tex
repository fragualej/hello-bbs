% Project Summary
\section{Project Summary}
\label{sec:summary}

This document presents a comprehensive technical proposal for developing a Roku channel application using modern development practices and industry best standards. The project encompasses a complete development lifecycle from initial setup through certification and deployment.

\subsection{Project Scope}
The Daystar Roku App development project focuses on creating a robust OTT (Over-The-Top) streaming application optimized for the Roku platform. The solution implements a scalable architecture supporting both Live and Video-on-Demand (VOD) content delivery with professional-grade user experience and performance optimization.

\subsection{Technical Approach}
The development follows a structured MVC (Model-View-Controller) architecture specifically adapted for Roku's SceneGraph framework. Core technologies include BrightScript for application logic, XML-based SceneGraph components for UI development, and modern tooling with BrighterScript compiler for enhanced development efficiency.

\subsection{Key Features}
\begin{itemize}
    \item \textbf{Content Browsing:} Efficient grid-based navigation using native RowList components for optimal memory management
    \item \textbf{Video Playback:} Comprehensive VideoView wrapper supporting Live/VOD streaming, playlists, and advanced controls
    \item \textbf{API Integration:} Robust HTTP service layer with task-based threading and JSON parsing optimization
    \item \textbf{Focus Management:} Native component navigation leveraging Roku's built-in focus handling system
    \item \textbf{Performance Optimization:} Memory-efficient architecture designed for Roku's hardware constraints
\end{itemize}

\subsection{Development Timeline}
The project is structured as a 3-month development cycle organized into 6 two-week sprints, covering foundation setup, core development, API services integration, content management, deployment optimization, and certification preparation.

% Architecture & Design
\section{Architecture \& Design}
\label{sec:architecture-design}

\subsection{MVC Architecture for Roku Channels}
Roku channels follow a modified MVC pattern adapted for SceneGraph framework. The Model layer handles data management through repositories and API services. The View layer consists of SceneGraph XML components defining UI structure and layout. The Controller layer uses centralized BrightScript logic attached to MainScene for coordinating application flow and handling cross-component communication.

\subsection{Model Layer}
Located in \texttt{src/components/tasks/} for HTTP communication (httpTask) and \texttt{src/components/models/} for data structures. Models handle API communication, business logic, and data serialization.

BaseModel classes provide common functionality for data validation and transformation. Repository classes manage data access and caching strategies for optimal performance on Roku devices.

\subsection{View Layer}
SceneGraph XML files in \texttt{src/components/views/} define the visual structure and layout. Each view component has corresponding BrightScript files for initialization and basic UI logic. Views communicate through observer patterns and field binding, maintaining separation from business logic.

\subsection{Controller Layer}
Located in \texttt{src/components/uiLogic/}, BrightScript scripts attached to MainScene manage application-wide coordination through observers. Controllers handle ItemFocused and ItemSelected events from UI components, manage ScreenStack for navigation flow between views.

Additionally, controllers coordinate analytics tracking across the channel, manage TextToSpeech parsing for accessibility, and orchestrate the overall application state and transitions.

This architecture ensures maintainable code organization while leveraging Roku's SceneGraph strengths for TV interface development.

% Focus Handling
\subsection{Focus Handling}
\label{sec:focus-handling}

Focus management is a critical aspect of Roku application development, as users navigate through the interface using remote control directional keys. The Roku framework provides a robust focus handling system centered around the \texttt{onKeyEvent} function and native built-in navigation.

\subsubsection{The onKeyEvent Function}
\label{sec:onkeyevent}

The \texttt{onKeyEvent} function is the primary mechanism for handling remote control input in Roku applications. This function receives two parameters: \texttt{key} (string) containing the key name ("OK", "back", "up", "down", etc.) and \texttt{press} (boolean) indicating whether it's a press or release event. The function should return \texttt{true} to consume the event or \texttt{false} to allow it to bubble up to parent components. Always check \texttt{press = true} to handle only key press events and avoid duplicate actions.

\subsubsection{Native Component Navigation}
\label{sec:native-navigation}

Roku's native components like \texttt{RowList}, \texttt{MarkupList}, \texttt{MarkupGrid}, \texttt{TargetGroup}, \texttt{ButtonGroup}, and \texttt{LabelList} provide built-in navigation handling that automatically manages focus transitions without requiring custom \texttt{onKeyEvent} implementations. Simply assign focus to these components using \texttt{componentName.setFocus(true)} and they will handle all directional navigation, focus boundaries, visual indicators, and scroll behavior internally. This approach reduces code complexity while ensuring consistent navigation patterns optimized for TV interfaces.

% API Services
\section{API Services}
\label{sec:api-services}

The API service layer provides structured HTTP communication and data management components for external service integration. Critical to performance, JSON parsing must be performed in the Task Thread to avoid blocking the SceneGraph Thread. Roku devices have a limitation of 50-100 concurrent Task nodes, requiring careful thread management and pooling strategies.

The flow follows a circular pattern: View $\rightarrow$ HttpNode $\rightarrow$ Repository $\rightarrow$ HttpTask $\rightarrow$ HttpNode $\rightarrow$ View.

\subsection{HttpTask}
\label{sec:httptask}

Handles individual HTTP requests with URL, headers, and request body configuration. Manages request lifecycle and response parsing for REST API calls.

\subsection{HttpNode}
\label{sec:HttpNode}

Content node that serves as a bridge between the SceneGraph Thread and Task Thread for HTTP operations. This component avoids Rendezvous patterns, which are not recommended for Roku apps when transferring large data objects through AssocArrays. HttpNode manages multiple HttpTasks and provides observable response handling while maintaining thread safety.

\subsection{Model}
\label{sec:model}

ContentNode that serves as a template for organizing data by setting fields for later use in Grids or VideoPlayer components. This approach is recommended by Roku for faster node creation and efficient data management. Models provide common serialization, validation, and property mapping for API response objects, standardizing data transformation between JSON and Roku objects.

\subsection{Repository}
\label{sec:repository}

Data access layer responsible for initializing HttpTask component and coordinating API communication. Repository handles URL mapping, API key injection, HTTP method configuration (GET, POST), ModelType specification, and request queuing. This component is attached to MainScene and serves as the central coordination point between HttpTask, HttpNodes and Views, providing a clean API interface for business logic components.

\section{Grids \& Tiles}
\subsection{Grids}
Browsing is one of the most important feature in Roku apps, which is why using a native component as \texttt{RowList} component is recommended. This component provides essential benefits: efficient memory management, built-in navigation handling for both vertical rows and horizontal items, and event support through \texttt{rowItemFocused} and \texttt{rowItemSelected}.

\subsection{Tiles}
Tiles serve as foundational display components following an inheritance pattern. A \texttt{BaseTile} component establishes common functionality (image, title, metadata, helpers, utils) while specialized tiles like \texttt{ChannelTile} and \texttt{EpisodeTile} extend it with specific features and layouts.


\section{VideoView \& Playback}
Video playback is the core feature of Roku apps, making the VideoPlayer the most critical component. It must seamlessly handle Live and VOD streaming, individual content items, and playlists.

The recommended architecture suggests a VideoView wrapper that exposes essential events (\texttt{control}, \texttt{state}, \texttt{position}, \texttt{duration}) and playlist parameters: \texttt{jumpToItem}, \texttt{currentIndex}, \texttt{isContentList}. This wrapper enables future implementations as:

\begin{itemize}
    \item Custom UI development for metadata display and progress bar
    \item Trickplay functionality (rewind, fast-forward, seek)
    \item Roku Advertising Framework (RAF) integration
\end{itemize}

% Deployment & Optimization
\section{Deployment \& Optimization}
\label{sec:deployment}

The deployment phase involves creating the final channel package and optimizing performance for submission to the Roku Channel Store. This critical phase ensures the application meets production standards and certification requirements.

\subsection{Package Creation}
The deployment process begins with generating a signed channel package using a Roku device. The channel must be side-loaded and thoroughly tested on actual hardware to validate functionality across different Roku device models and firmware versions. This step verifies that all components work correctly in the production environment.

\subsection{Performance Optimization}
Prior to certification submission, the channel undergoes comprehensive optimization including memory usage analysis, startup time improvements, and UI responsiveness testing. Performance metrics must meet Roku's standards for smooth operation across all supported device tiers, from entry-level to premium models.

\subsection{Pre-Certification Validation}
The final package is validated against Roku's certification criteria, ensuring compliance with technical requirements, UI guidelines, and content standards. This includes testing navigation patterns, error handling, and accessibility features to guarantee a seamless user experience before official submission.

\section{Certification Process}
\label{sec:certification}

The Roku certification process ensures channels meet platform standards for functionality, performance, and user experience before publication to the Roku Channel Store.

\subsection{Certification Requirements}

Roku certification ensures channels meet platform standards across multiple criteria areas.

The complete certification requirements are available at:
\url{https://developer.roku.com/docs/developer-program/certification/certification.md}

\subsubsection{Certification Criteria Overview}
The certification process evaluates channels across the following areas:
\begin{enumerate}
    \item Advertising
    \item Purchases
    \item Performance
    \item Channel Operation
    \item Deep Linking
    \item UI and Graphics
\end{enumerate}

\subsubsection{Free App Certification Focus}
It should first identify the app type and features to determine relevant certification requirements. For example, a \textbf{Free App without Advertising, Purchases, or Deep Linking} would focus on the following applicable criteria:

\textbf{3. Performance:} Memory optimization, startup performance, and thread management to ensure smooth operation across all Roku device tiers.

\textbf{4. Channel Operation:} Navigation flow, error handling, content playback reliability, and proper remote control integration for seamless user experience.

\textbf{6. UI and Graphics:} Visual consistency, accessibility compliance, and adherence to Roku design guidelines for professional channel presentation.

\subsection{Submission Process}
The certification workflow involves channel package preparation, testing validation, and Roku review process for final approval and Channel Store publication.
